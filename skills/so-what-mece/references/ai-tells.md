# AI 문체 걷어내기

초안에서 기계가 쓴 티가 나는 표현을 찾아 고치는 목록이다. 분류는 [epoko77-ai/im-not-ai](https://github.com/epoko77-ai/im-not-ai)(MIT)를 참고해 업무 문서에 자주 나오는 것만 추렸다. 한국어 문서를 기준으로 한다.

## 먼저 지킬 것

- 수치, 날짜, 단위, 고유명사, 제품명, 인용문은 한 글자도 바꾸지 않는다.
- 업계에서 그대로 쓰는 영어 약어(API, KPI 등)는 그대로 둔다.
- 원문에 없던 비유, 꾸밈, 문학적 표현을 새로 넣지 않는다.
- 격식 수준을 바꾸지 않는다. 보고서가 블로그 글처럼 되면 안 된다.
- 기존 글을 고칠 때는 필요한 만큼만 고친다. 절반 넘게 바뀌었다면 지나치게 고친 것이니 되돌아가 다시 본다.

## 1. 번역투

| 표현 | 고치는 방법 | 예 |
|---|---|---|
| ~에 대해(서) | 목적격 조사로 바로 잇기 | 가격에 대해 논의 → 가격을 논의 |
| ~를 통해 | ~로, ~해서 | 설문을 통해 확인 → 설문으로 확인 |
| ~에 있어(서) | ~에서 | 운영에 있어서 → 운영에서 |
| ~와 관련하여 | ~에, ~의 | 환불과 관련하여 → 환불에 |
| ~에 기반하여 | ~로, ~을 보고 | 데이터에 기반하여 → 데이터로 |
| ~를 가지고 있다 | 형용사나 동사로 | 강점을 가지고 있다 → 강하다 |
| 회의를 가지다 | 동사로 | 회의를 가졌다 → 회의했다 |
| ~되어진다 | 능동이나 단일 피동 | 판단되어진다 → 판단된다 |
| ~에 의해 | 행위자를 주어로 | 팀에 의해 작성된 → 팀이 작성한 |
| ~을 위해 남발 | ~려고, ~용 | 개선을 위해 → 개선하려고 |
| ~에서의, ~으로의 | 풀어 쓰기 | 현장에서의 대응 → 현장 대응 |
| 긴 꾸밈말이 명사 앞에 몰림 | 문장을 나누기 | 세 어절 넘는 꾸밈말은 뒤 문장으로 |

## 2. 상투적인 표현

| 표현 | 고치는 방법 |
|---|---|
| 결론적으로, 요약하면, 정리하면 | 지운다. 결론은 제목과 첫 줄에 이미 있다 |
| 시사하는 바가 크다, 주목할 만하다 | 지우고 무엇을 뜻하는지 구체적으로 쓴다 |
| 본질적으로, 핵심적으로, 근본적으로 | 지운다 |
| 획기적, 압도적, 강력한, 파격적 | 수치와 사실로 바꾼다 |
| ~할 때다, 지금이야말로 | 평서문으로 닫는다 |
| 'A에서 B로' 틀의 반복 | 한 번만 쓴다 |
| 기술이 묻는다, 시장이 말한다 | 사람이나 조직을 주어로 쓴다 |
| ~인 것이다, ~라는 점에 있다 | '~다'로 바로 쓴다 |
| ~다는 의미다, ~다는 뜻이다 | 본문에 풀어 쓴다 |

## 3. 접속사와 지시어

- 문장 첫머리의 '또한', '따라서', '즉', '나아가', '아울러', '게다가', '더욱이'를 지운다. 불릿과 번호가 이미 순서를 보여 준다.
- '이는', '이 점에서', '이러한 관점에서'로 시작하는 문장은 앞 문장에 붙이거나 주어를 구체적으로 쓴다.
- '먼저 ~, 반면 ~, 결국 ~'처럼 세 단계로 맞춘 틀을 되풀이하지 않는다.

## 4. 얼버무림

| 표현 | 고치는 방법 |
|---|---|
| ~할 수 있다 남발 | 확인된 것은 단정한다(높일 수 있다 → 높인다) |
| ~로 보인다, ~인 듯하다 | 확인된 것은 단정하고, 확인되지 않은 것은 '추정'이라고 밝힌다 |
| ~할 것이다 남발 | 현재형이나 확정형으로 쓴다 |
| 장점도 있지만 단점도 있다 | 어느 쪽인지 판단을 쓴다 |
| 신중한 검토가 필요하다 | 누가 언제까지 무엇을 검토하는지 쓴다 |

얼버무림을 없앤다고 근거 없는 내용을 단정하면 안 된다. 근거가 있으면 단정하고, 없으면 '추정' 또는 '미확인'으로 분명히 적는다. 그 사이의 흐릿한 표현만 걷어낸다.

## 5. 영어 병기

- 한글 뒤에 괄호로 영어를 매번 붙이지 않는다. 처음 한 번만 병기한다.
- 우리말로 옮길 수 있는 영어 단어는 옮긴다. 업계에서 굳은 용어와 팀이 정한 지표명은 그대로 둔다.

## 6. 장식

- 이모지를 쓰지 않는다. 상태 표시가 꼭 필요하면 도구의 상태 기능이나 글자('완료', '진행 중')로 쓴다.
- 따옴표로 단어를 강조하지 않는다. 따옴표는 인용과 명칭에만 쓴다.
- 굵은 글씨는 블록마다 한 줄만 쓴다.
- 줄 중간의 줄표(—, –)를 쓰지 않는다. 구분에는 ` : `를 쓴다. 줄 맨 앞의 불릿 기호 `-`는 그대로 쓴다.
- '(1), (2), (3)'처럼 문장 속에 번호를 끼워 넣지 않는다. 불릿이나 번호 목록으로 뺀다.
- '-고', '-며', '-지만' 바로 뒤에 쉼표를 찍지 않는다.

## 7. 리듬

- 모든 불릿이 같은 길이, 같은 끝말로 끝나면 기계적으로 보인다. 내용이 짧으면 짧게, 길면 길게 둔다.
- 불릿을 세 개씩 맞추려고 내용을 늘리거나 줄이지 않는다. 있는 만큼만 쓴다.
- '-성', '-적', '-화'가 붙은 말이 줄줄이 이어지면 동사와 형용사로 푼다(효율성 제고를 위한 최적화 → 더 빠르게 처리하도록 고치기).
- 문장으로 쓰는 단락에서는 같은 종결어미가 네 번 넘게 이어지지 않게 한다.

## 이 스킬의 규칙과 겹치는 부분

- 원 자료는 '제목 : 부제' 꼴의 제목 반복을 AI 문체로 보지만, 이 스킬은 업무 문서의 제목을 '이름 : 결론' 꼴로 통일한다. 업무 문서에서는 일관된 틀이 읽는 속도를 높이기 때문이다. 대신 부제는 꾸밈말이 아니라 결론이어야 한다.
- 원 자료는 칼럼과 리포트에서 불릿을 줄이라고 하지만, 이 스킬이 다루는 업무 문서는 개조식이 기본이다. 칼럼이나 긴 산문을 고칠 때는 원 자료를 따른다.

## 고치기 전과 후

```
고치기 전:
결론적으로, 이번 개편은 고객 경험에 있어서 획기적인 변화를 가져올 수 있을
것으로 보입니다. 또한, 데이터에 기반하여 살펴보면 재방문율에 대해 긍정적인
영향을 미쳤다는 점에서 시사하는 바가 큽니다.

고친 뒤:
- 개편 후 재방문율 상승 : 전체 고객으로 확대
  - 재방문율 18% → 24%
  - 개편 적용 고객 1,200명 기준, 4주 관찰
```
